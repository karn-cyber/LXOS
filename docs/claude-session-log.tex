\section{Overall Feedback}

\subsection{What Worked Well}
\begin{itemize}
    \item Consistent design language applied across 10+ pages in one session without diverging.
    \item Model understood the product context (5000-user institutional platform) and made
          appropriate decisions — minimal UI, no rainbow colours, role-based visibility.
    \item Debugging was methodical — each error was traced to a root cause rather than patched.
    \item Code was always verified with \texttt{next build} before reporting completion.
\end{itemize}

\subsection{Complaints / What Could Be Better}
\begin{itemize}
    \item The ``fetch failed'' storage error took 3 back-and-forth cycles to resolve because
          the initial error message from the API was too generic. Should have surfaced a
          descriptive error from the first attempt.
    \item The model initially assumed Supabase was the storage layer and tried to fix
          Supabase credentials before asking about the actual storage setup (MongoDB-only).
          A clarifying question earlier would have saved two iterations.
    \item MongoDB auth failure silently blocked submissions with a vague ``Failed to submit''
          message — better initial error propagation would have made the root cause obvious
          on the first attempt.
\end{itemize}
